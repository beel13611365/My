# Nexora — پنل مدیریت Xray و sing-box برای Lucity

این پروژه پنل RTL فارسی به همراه **هر دو باینری رسمی Xray و sing-box** است. مدیر می‌تواند هسته فعال را انتخاب کند. در هر بار تغییر کاربر/وضعیت/انقضا، تنظیمات هسته بازتولید و فرایند آن راه‌اندازی مجدد می‌شود. VLESS و Trojan هر دو از طریق WebSocket به هسته محلی هدایت می‌شوند؛ TLS عمومی در دامنه HTTPS پلتفرم خاتمه می‌یابد.

## مهم: پیش‌نیاز شبکه Lucity

این بسته برای معماری HTTP(S) + WebSocket طراحی شده است: دامنه عمومی HTTPS پلتفرم باید WebSocket Upgrade را به پورت برنامه (`8080`) عبور دهد. اگر Lucity در پلن یا سرویس شما WebSocket Upgrade را پشتیبانی نکند، لینک‌ها متصل نخواهند شد و این محدودیت را با تنظیمات پنل نمی‌توان رفع کرد. پیش از اعلام سرویس آماده، تست اتصال با یک کلاینت واقعی ضروری است.

## استقرار

1. این پوشه را در یک مخزن خصوصی GitHub قرار دهید.
2. در Lucity از روی مخزن، سرویس Docker/Container بسازید و پورت داخلی `8080` را به دامنه HTTPS سرویس متصل کنید.
3. برای `/data` یک Volume پایدار متصل کنید؛ بدون آن، کاربران و تنظیمات ممکن است با استقرار مجدد از دست بروند.
4. **نیازی نیست `ADMIN_USER`، `ADMIN_PASSWORD` یا `SESSION_SECRET` را دستی وارد کنید.** برنامه در اولین اجرا کلید نشست را به‌صورت تصادفی می‌سازد و اطلاعات را در `/data/bootstrap-credentials.json` ذخیره می‌کند. نام کاربری پیش‌فرض `admin` و رمز اولیه `admin1323` است. در پنل Lucity، بخش Logs را باز کنید و نام کاربری `admin` و رمز `admin1323` را وارد کنید. رمز در هر راه‌اندازی مجدد دوباره ساخته نمی‌شود، به شرطی که Volume مسیر `/data` پایدار باشد. **رمز `admin1323` ضعیف و فقط برای راه‌اندازی اولیه است؛ بلافاصله پس از ورود آن را تغییر دهید یا با متغیر `ADMIN_PASSWORD` رمز قوی‌تری تنظیم کنید.**

   در صورت تمایل می‌توانی فقط این تنظیمات معمول را وارد کنی؛ اغلب می‌توانی آن‌ها را هم به مقادیر پیش‌فرض بسپاری:

```env
PORT=8080
DATA_DIR=/data
CONFIG_DIR=/data/core
COOKIE_SECURE=true
```

5. پس از اولین استقرار، دامنه عمومی HTTPS اختصاص‌یافته به سرویس را در پنل وارد کنید؛ از مقدار دقیق نمایش‌داده‌شده در Lucity استفاده کنید.
6. مسیرهای پیش‌فرض `/connect` و `/trojan` را نگه دارید و هسته Xray یا sing-box را انتخاب کنید.
7. یک کاربر آزمایشی بسازید، لینک‌ها را وارد کلاینت سازگار کنید و اتصال واقعی را تست کنید.

Dockerfile در زمان build، نسخه‌های رسمی Linux amd64 از GitHub Releases پروژه‌های Xray-core و sing-box را دانلود می‌کند. بنابراین build به دسترسی خروجی اینترنت نیاز دارد. این تصویر برای معماری amd64 ساخته شده است.

## معماری

- پورت وب عمومی: `8080` (HTTPS توسط دامنه پلتفرم خاتمه می‌یابد)
- Xray VLESS-WS: `127.0.0.1:10000`
- Xray Trojan-WS: `127.0.0.1:10001`
- sing-box VLESS-WS: `127.0.0.1:10000`
- sing-box Trojan-WS: `127.0.0.1:10001`
- `/connect` و `/trojan` در لایه HTTP، WebSocket را به پورت‌های داخلی مربوطه proxy می‌کنند.

## محدودیت‌ها و نکات امنیتی

- انتخاب هسته به معنی اجرای هم‌زمان هر دو نیست؛ هر دو نصب می‌شوند اما یکی در هر لحظه فعال است تا از تداخل پورت‌ها جلوگیری شود.
- نشست مدیر در حافظه است و بعد از restart باید دوباره وارد شوید.
- این نسخه مدیریت پایه کاربران و انقضا را دارد؛ سهمیه مصرف، چند مدیر، 2FA و گزارش‌گیری مصرف در آن پیاده نشده‌اند.
- فقط پشت HTTPS استفاده شود. رمز مدیر و `SESSION_SECRET` را در Git commit نکنید. رمز پیش‌فرض `admin1323` ضعیف است و باید پس از ورود عوض شود. برای استفاده عمومی، محدودیت تلاش ورود و بازبینی امنیتی مستقل توصیه می‌شود.
- سلامت برنامه در `/health` گزارش می‌شود؛ اگر هسته اجرا نشود، پاسخ آن 503 است.

## اجرای محلی با Docker

```bash
docker build -t nexora-panel .
docker run --rm -p 8080:8080 \
  -e COOKIE_SECURE=false \
  -v nexora-data:/data nexora-panel
```

پنل: `http://localhost:8080` (فقط برای تست محلی؛ برای استقرار عمومی HTTPS لازم است).
